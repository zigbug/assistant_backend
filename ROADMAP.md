# Roadmap: Assistant Backend & MCP Integration

## Архитектурные решения (зафиксировано)
- **MCP-сервер**: будет реализован отдельно (Dart или Go), развернут на сервере, бэкенд будет предоставлять ему HTTP/gRPC API.
- **AI-логика**: временно делегируется десктопному приложению Qwen (бэкенд выступает как хранилище данных и источник контекста).
- **Аутентификация**: пока используем простой `API_KEY` в заголовках. JWT/OAuth2 добавим позже по мере необходимости.
- **Время**: все даты и время (`DateTime`) в базе данных и API строго в **UTC**. Конвертация в локальный часовой пояс происходит на стороне клиента (Flutter) с учетом `timezone` из `Preferences`.

## Этап 1: База данных и DAO (Текущий приоритет)
- [x] Инициализация проекта и настройка Drift (PostgreSQL + SQLite для локальной разработки).
- [x] Определение схемы БД (таблицы: `Projects`, `Tasks`, `Events`, `DailyPlans`, `DailyPlanItems`, `Preferences`, `Notes`, `AiLessons`).
- [ ] Реализация DAO (Data Access Objects) для всех таблиц:
  - [ ] `TasksDao`: CRUD операции, фильтрация по статусу/проекту, получение задач на сегодня.
  - [ ] `ProjectsDao`: CRUD операции.
  - [ ] `DailyPlansDao` и `DailyPlanItemsDao`: создание плана, привязка задач к временным слотам.
  - [ ] `PreferencesDao`: чтение/запись настроек (включая `timezone`).
  - [ ] `AiLessonsDao`: добавление и получение контекста для обучения агента.
- [ ] Написание unit-тестов для DAO (с использованием SQLite in-memory).

## Этап 2: HTTP API (Shelf)
- [ ] Настройка базового `shelf` сервера с middleware:
  - Логирование запросов.
  - Проверка `API_KEY`.
  - Обработка CORS (для локальной разработки).
- [ ] Реализация REST-эндпоинтов:
  - `GET /health` - проверка работоспособности.
  - `GET /api/v1/tasks`, `POST /api/v1/tasks`, `PUT /api/v1/tasks/:id`, `DELETE /api/v1/tasks/:id`.
  - `GET /api/v1/projects`, `POST /api/v1/projects`, и т.д.
  - `GET /api/v1/daily-plans/:date` - получение плана на конкретную дату (UTC).
  - `POST /api/v1/daily-plans/generate` - эндпоинт-заглушка или базовая логика инициации генерации плана (для будущего вызова из MCP/Qwen).

## Этап 3: Интеграция с MCP (Будущий этап)
- [ ] Проектирование и документирование OpenAPI/Swagger спецификации для MCP-сервера.
- [ ] Реализация специфичных эндпоинтов для MCP (например, пакетное получение контекста: задачи + предпочтения + последние уроки AI).
- [ ] Выбор стека для MCP (Dart `mcp` пакет или Go) и инициализация отдельного репозитория.

## Этап 4: CI/CD и Деплой
- [ ] Настройка GitHub Actions для тестирования и линтинга.
- [ ] Dockerfile для бэкенда.
- [ ] Развертывание на VPS (Ubuntu) с использованием Docker Compose (бэкенд + PostgreSQL).
